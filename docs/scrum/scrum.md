### 강사님 피드백

**개인 말투(Voice) 입력 방식**
- 말투 문장은 매번 쓰는 게 아니라 **첫 1회 팝업** + 이후 **마이페이지에서 수정**.
- 말투 질문의 근거: **사람 성격이 드러나는 상황별 문장**(당황·서운함·미안함·거절·설렘)을 넣음.
- ⚠️ **회원가입·설문은 사용자에겐 귀찮음.** "나만의 말투 설정"을 **AI로 자동화**하면 서비스가 더 좋아짐.
  - 방향: **개인 휴대폰에서 웹/데이터를 긁어 → 비식별화 → 서버로 보내 분석** → 나만의 말투를 탑재한 소설.
  - **비식별화 필수.** 온디바이스 모델(젬마4/젬마 나노 등 휴대폰 동작 모델)도 검토 가능.

**피드백/추천 로직**
- 일단 **프롬프트로 작가 말투·컨셉 반영(API)**, **컨셉이 확실해지면 RAG 적용** 예정. 컨셉별 피드백 확인 후 프롬프트 수정.
- 작가 추천 대사에 **RAG 적용 시 사용자 특화 대사**가 나올지 → **실험 필요**(프롬프트에 변수 넣어 판단·제안하며 사용자화).
- **장르 추천부터 사용자 기반**으로 가면 좋음.

**AI 휴먼 / 연출**
- 사용자 입력에 따라 **이벤트 발생 시 작가 영상 재생 + 리액션**.
- **작가 답변의 첫 대사를 TTS로 낭독**.

**AI 철학 (중요)**
- "우리가 예측 못 하는 걸 AI가 — **패턴 추출·대화 이해**를 써먹으려 AI를 쓰는 것."
- **rule 기반은 한계가 분명** → **AI로 동적으로 만들면 계속 진화**.

**오탈자/맞춤법**
- **실시간 교정·마킹은 헤비하고 식상** → 지양.
- 대신 **작가 AI가 "너 또 맞춤법 틀렸네" 식으로 언급**하는 연출은 고려 (원래 기획 아님, 애자일).

**🔴 개인 데이터 RAG = 차별성의 핵심**
- **"흐름 관리는 LLM이 잘함 → LLM이 *못하는 것*을 써라."**
- **서버에서 사용자 행동(오타 빈도·입력 패턴·체류시간·말투)을 수집 → RAG로 문체/추천에 반영.** = "개인 DB 반영 파트". 여기서 차별성이 나옴.
- 개인 취향을 파악한 추천 시스템. 테스트는 "사용자 취향이 반영되는지" 확인.

**🔴 정량 평가/테스트 결과 없음**

- 생성물을 다른 AI 분류모델로 돌려 장르가 어떻게 나오는지(사람 판단 말고).

**기타**

- 세계관: 사용자 입력 + 랜덤 추천(어제 논의분 미반영).
- 고객층 10~30대.
- **1팀: 스크럼 녹화 + 참석/이해 여부 기재.**

- **AI휴먼식 이벤트성 강화** — 오타·세계관 붕괴 시 안내, 요약 안내 멘트, 중간에 휴먼(아바타)이 등장해 사람 느낌을 주는 방식
- **타겟 연령층 확실히**
- **API 토큰(비용) 고려**
- **DB** — PostgreSQL만 써도 무방. 연습 삼아 MySQL에 JSON으로 넣어보거나, 로컬 DB에서 RDB/NoSQL을 함께 써보는 것도 권장
- 모델을 쓰면 RAG 벡터 임베딩이 필요할 수 있음

### 팀 해석 / 결정 (2026-06-08 정리)
- **서비스 정의 확정**: "ChatGPT는 밖에서 지시하는 *도구*, NodeVelture는 사용자가 이야기 *안에 들어가는 무대*."
- **차별점 3축** (추리극 오해와 무관하게 성립): ① 사용자가 1인칭 주인공으로 참여 ② 작가 페르소나와 협업 창작 ③ 대화 → 소설 자동 변환
- **RAG 재정의**: "캐릭터별 비밀정보 분리"(추리극 오해 기반)가 아니라 **세계관·설정 일관성(장기 기억)** 용도.
  대화가 길어져도 마을 이름·캐릭터 성격·이전 사건을 까먹지 않게 검색 주입 (제미나이의 컨텍스트 설정붕괴 보완).
- **RAG 범위**: 마감(6/19) 고려해 **RAG-lite 우선** — 이전 세계관 설정·사건 요약을 프롬프트에 주입. 여유 시 pgvector 벡터 검색으로 확장.
- **타겟 연령**: **2030 취미 창작러** (로판/추리/현대 장르 유지, 웹소설 친화).
- **AI휴먼 이벤트성**: 아바타 4트리거(진입 인사 / 세계관 붕괴·오타 안내 / N턴 요약 멘트 / 완성 축하) — MVP는 진입+요약 최소 구현.
- **문체 모델(유득님)**: 소설 변환 3단계 후처리로 부착 → [문체모델 연동 설계](../문체모델_연동_설계.md).

### 1. 차별화 (최우선)
- 발표 때 반드시 나올 질문: **"ChatGPT에 채팅하는 것과 뭐가 다르냐"** → 방어 논리 필수

### 2. RAG 도입 (기술적 핵심 차별점)
- 캐릭터마다 **자기만 아는 정보**를 RAG로 부여 → 서로 모르는 상태에서 대화 → 살아있는 NPC 느낌
- 예) 민준=잠입 형사 배경·받은 명령 / 지수=민준을 좋아하는 사실·친구 관계망 / 의문의 손님=사실은 형사 동료·작전 계획
- 발화 시 자기 RAG에서만 정보를 꺼냄

> ⚠️ **(2026-06-08 팀 결정) 이 "캐릭터별 비밀정보 분리" 항목은 채택하지 않음.**
> 강사님이 우리 서비스를 **추리극(AI 찾기 게임)으로 오해**한 맥락에서 나온 피드백.
> 빙의작가 서비스의 핵심 차별점으로는 부적합 → RAG는 아래 6/5 결정대로 **"세계관 일관성(장기 기억)"** 용도로 재정의.

### 3. 자체 모델 + 전후처리 (강사님 강조)
- **상용 API 지양**, 자연어는 **Qwen 2.5**가 가장 좋음
- 전처리(입력 정제·의도 파악) + 후처리(응답 품질 검증·페르소나 일관성 체크) 모델을 끼면 **성능 입증 가능**
- EXAONE은 비추(폐쇄망용)

### 4. 퍼포먼스 강화
- 첫 화면에서 **아바타가 캐릭터 대표 대사를 음성으로** → 진입 순간부터 몰입 (PERSO Avatar 활용처 명확화)

### 5. 서비스 레벨 확장 (프로덕트 사고)

- 3주 안에 다 못 만들어도 **발표에 포함하면 점수 큼**

### 6. 삽화 생성 (멀티모달 확장)

  > ※ 이후 6/5 스크럼에서 "PostgreSQL only로도 무방"으로 완화됨
