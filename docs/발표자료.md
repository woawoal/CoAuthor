## 5. 프로젝트 개요

- **서비스 정의**: 사용자가 AI와 세계관을 설계하고, 그 세계 속 **주인공이 되어** 조연(AI)과 대화하다 보면 **소설 초안이 완성**되는 협업 창작 플랫폼
- **3단계 핵심 흐름**

```
① 세계관 설정      ② 대화형 창작              ③ 소설 변환
AI와 장르·배경·   사용자=주인공 /            대화 로그 →
등장인물 설계  ─▶  AI=나레이션·조연 다수  ─▶  작가 문체의 단편소설
                  (기억·검수 RAG로 일관성)    (문체 RAG few-shot)
```

- **결과물**: 대화 로그가 **작가 문체의 단편 소설**로 자동 변환 → 읽기·삽화·내보내기

🎙️ *"핵심은 '쓰는' 게 아니라 '대화하는' 겁니다. 대화가 끝나면 소설이 남습니다."*

## 6. 주제 선정 배경

- **창작 욕구는 큰데 진입 장벽은 높다** — 웹소설·웹툰 소비는 폭발하지만, *직접 쓰는* 사람은 극소수
- **"AI로 소설? ChatGPT로 되잖아"** 라는 통념 — 실제로 써보면 **긴 맥락에서 설정을 흘리고, 모순을 통과시키고, 문체가 안 남는다**
- 생성형 AI 대중화로 *도구*는 많아졌지만, **끝까지 같이 가는 '파트너'** 는 없다
- → 우리는 *도구*가 아니라 **쓸수록 나를 아는 창작 파트너**를 만들기로 했다. 그리고 그 차별을 **말이 아니라 수치로** 증명한다.

🎙️ *"발표 내내 '말'이 아니라 '숫자'로 차별점을 보여드리겠습니다."*

## 7. 문제 정의

| # | 사용자가 겪는 문제 | NodeVelture의 해법 |
|---|--------------------|---------------------|
| ① | **빈 화면 공포** — 첫 문장이 안 써짐 | 작가 선택 + 세계관 폼 → AI가 **첫 장면을 던져줌** |
| ② | **설정 붕괴** — 길어지면 앞 설정을 까먹음 | **기억 RAG** — 오래된 설정을 의미검색해 재주입 |
| ③ | **모순 통과** — "아까 형사라며?"를 못 잡음 | **검수 RAG** — 새 문장 ↔ 설정 모순 탐지 |
| ④ | **내 문체가 안 남음** | **문체 RAG** — 작가 문체 예시 few-shot 주입 |
| ⑤ | **혼자라 안 이어짐** | 작가 리액션·개인화로 *끝까지 같이* 씀 |

🎙️ *"이 다섯 문제를, 기억·검수·문체 세 축으로 풉니다."*

## 8. 서비스 기획 방향

- **컨셉**: 진지한 창작 도구(척추) + 엔터테인먼트(껍데기)
- **둘을 잇는 다리** = *"작가 캐릭터와 놀듯 대화 → 진짜 내 소설"*
- **역할 분담**: 사용자는 **주인공**(능동적 1인칭 참여), AI 작가는 **나레이션·등장인물·문체** 담당
- **설계 경계(중요)**: 개인화는 *코치/추천 층*에만 — **소설 출력 문체엔 개인 정체성을 주입하지 않음**(작가 페르소나의 순도 유지)

🎙️ *"재미있게 '놀듯' 들어오지만, 남는 건 진지한 '내 소설'입니다."*

## 9. 서비스 소개

**작가를 고르면 말투·장르·문체·화면 톤이 통째로 바뀐다 — AI 작가 4인**

| 작가 | 장르 | 말투·문체 | 테마 |
|------|------|-----------|------|
| **백야** | 호러·미스터리 | 담담하고 건조한 반말 | 다크 |
| **차로운** | 본격 추리 | 분석적·또박또박 존댓말 | 다크 |
| **한여름** | 로맨스 | 다정하고 살가운 말투 | 라이트 |
| **김도현** | 일상·에세이 | 편안하고 따뜻한 말투 | 라이트 |

- 페르소나 = **시스템 프롬프트 + 문체 예시(few-shot)** 로 구현
- 사용 흐름: **작가 선택 → 세계관 폼 → 대화형 창작 → 「채팅 종료」 → 소설 변환 → 읽기·삽화**

🎙️ *"작가는 단순 톤이 아니라, 말투·장르·문체·화면 색까지 통째로 바뀌는 4개의 세계입니다."*

## 12. 차별화 포인트 — SWOT 분석

| **Strengths (강점)** | **Weaknesses (약점)** |
|----------------------|------------------------|
| · RAG 3종(기억·검수·문체) **수치로 증명** | · 단편 규모 → 인앱 코사인(벡터DB 미도입) |
| · 작가 4인 페르소나 + 문체 few-shot | · 문체 RAG 마진 작음(규칙이 이미 강함) |
| · 멀티모달(TTS·삽화·BGM) | · 콜드스타트·DB 리전 지연 |
| · 풀스택 풀사이클 + 엔진 스위치/폴백 | · 평가 샘플 수 제한 |

| **Opportunities (기회)** | **Threats (위협)** |
|--------------------------|---------------------|
| · 웹소설·숏폼 창작 수요 확대 | · 범용 LLM(ChatGPT 등)의 보편화 |
| · 생성형 AI 대중화 | · 외부 API 할당·비용·IP 차단 |
| · 개인화 확장(예측형 추천) | · 생성물 저작권 이슈 |
| · B2B(작가 보조 도구)·교육 | · 후발 유사 서비스 |

- **핵심 차별**: 범용 LLM이 *"못/안 하는"* **기억·검수·문체**를 하고, **그걸 수치로 증명** + **대화→소설 변환**으로 결과를 남김

🎙️ *"강점은 살리고 약점은 개선 경로를 명확히 — 위협(범용 LLM)은 '수치 증명 + 변환'으로 정면 돌파합니다."*

## 14. 전체 시스템 구조

```
[클라이언트] React + Vite (반응형) — Vercel
      │ REST + SSE(스트리밍)
[백엔드]   FastAPI — GCP Cloud Run (상시 HTTPS)
      ├─ Neon PostgreSQL (대화·소설·로그)
      ├─ Upstash Redis (히스토리·캐시·상태)
      └─ 응답엔진/임베딩 → Vertex AI (폴백: Groq·OpenAI)

[AI 파이프라인]
사용자 입력(주인공) ─▶ 프롬프트 조립
   (페르소나 + 세계관 + [기억 RAG] + 메모 + 화자고정규칙)
        ▼  LLM (json 구조화 응답)
   {narration, dialogue, speaker, state}  ← 나레이션/대사 분리
        ├─▶ 검수 RAG(모순 탐지)
        └─▶ 화면: 타자기 렌더 + 작가 리액션 + TTS
「채팅 종료」 ─▶ 대화로그 ─[문체 RAG few-shot]─▶ 작가 문체 단편소설
```

- **응답엔진 선택**: 가이드 PERSO 1순위 / 제한 시 대체 LLM 동등 — 우리는 **엔진 스위치 구조**(`LLM_PROVIDER`·`USE_VERTEX`)로 **언제든 교체·폴백**

🎙️ *"한 엔진이 막혀도 환경변수 한 줄·자동 폴백으로 시연이 끊기지 않습니다."*

## 15. 주요 기능 소개

**① RAG 3종 — 차별점의 본체**

| 구분 | 모듈 | 한 줄 |
|------|------|-------|
| 기억 | `memory.py` | 오래된 대화를 **의미검색**해 재주입 → 안 까먹음 |
| 검수 | `consistency.py` | 새 응답 ↔ 설정 **모순 탐지** |
| 문체 | `style.py` | 작가 문체 예시 검색 → 변환 **few-shot 주입** |

**② 대화형 창작** — 주인공 대사 · `@등장인물` 조연 동시 반응 · **메모 즉시 주입** · 화자 고정(2겹)
**③ 소설 변환** — 「채팅 종료」 → 작가 문체 단편소설 → 읽기·내보내기
**④ 멀티모달** — TTS(작가 목소리 낭독) · 삽화(Vertex Image) · 작가별 BGM
**⑤ 개인화** — 맞춤법 **오답노트 능동 경고**(예측형) · 취향 프로파일 · **세계관 수정**(다음 대화 즉시 반영)

🎙️ *"기억·검수·문체로 '쓰는 일관성'을, 멀티모달·개인화로 '쓰는 경험'을 끝까지 받칩니다."*

## 16. 평가 지표

**측정 방식**: RAG 3종 **OFF vs ON**을 재현 스크립트로 비교 · 채점 **LLM-as-Judge 4축**(페르소나·문체·정확성·완성도, 다회 평균)

| RAG | 측정 | OFF | ON |
|-----|------|-----|-----|
| ① 기억 | 6턴 전 비밀("민준=잠입 형사") 회상 | **실패(못 떠올림)** | **정확 회상** ⭐ |
| ② 검수 | 설정 모순 탐지 | — | **정확 판별**(형사↔의사 `[high]`) |
| ③ 문체 | 문체 점수(3회 평균, 20점) | 17.33 | **18.33 (+1.00)** |

- **속도**: 응답엔진 Vertex 전환으로 **8초 → ~2초**, Groq 언어누수(한자/일본어) 해소
- **목표 지표**: 페르소나 일관성 LLM-Judge ≥4.0 · 캐릭터 구분도 코사인<0.6 · 응답 P95<5,000ms · 캐시 히트율>30%
- **정직한 한계**: 측정엔진 변동성→다회평균 / 문체 마진 작음→샘플풀 확대(`evidence_report.py`)

🎙️ *"①기억·②검수는 이미 압도적이고, ③문체는 양의 효과 + 개선 경로가 명확합니다."*

## 17. 구현 결과 및 시연 영상

> 상세 콘티: [데모_시나리오.md](데모_시나리오.md)

**시연 흐름**
① 작가 선택(테마 전환) → ② 세계관 폼 → ③ **대화형 창작**(주인공 대사 + @등장인물 + 메모 즉시주입=기억 RAG) → ④ **맞춤법 교정 + 오답 능동경고** → ⑤ **「채팅 종료」 → 작가 문체 소설 자동 변환** → ⑥ 읽기 + **삽화 생성** → ⑦ 마이페이지(서재·취향·오답노트)

- **라이브 증명 카드**: `rag_demo`를 즉석 실행 → OFF=못 떠올림 / ON=정확 회상
- **시연 안전수칙**: 사전 **백엔드 워밍업**(cold-start 회피) · 시드 데이터 · 변환 지연 시 백업 완성작 컷

🎙️ *"진짜 되냐 물으시면, RAG OFF/ON을 즉석에서 돌려 보여드리겠습니다."*
