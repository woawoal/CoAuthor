🎙️ *"안녕하세요. 저희는 'AI 작가와 대화하면 그게 내 소설이 되는' 서비스, NodeVelture를 만들었습니다."*

🎙️ *"발표 내내 '말'이 아니라 '숫자'로 차별점을 보여드리겠습니다."*

# PART 1 — 기획 (5분)

## 🖥️ S3. 페르소나 정의 — 우리가 만든 것 *(기획필수 ②)*
- **컨셉**: 진지한 창작 도구(척추) + 엔터테인먼트(껍데기). 둘을 잇는 다리 = *"작가 캐릭터와 놀듯 대화 → 진짜 내 소설"*
- 사용자는 **주인공**이 되어 대화하고, AI 작가는 **나레이션·등장인물·문체**를 맡는다.
- 결과물: 대화 로그 → **작가 문체의 단편 소설**.

## 🖥️ S4. 페르소나 카드 — AI 작가 4인 *(가이드 §7)*

| 작가 | 장르 | 말투·문체 | 테마 |
|------|------|-----------|------|
| **백야** | 호러·미스터리 | 담담하고 건조한 반말 | 다크 |
| **차로운** | 본격 추리 | 분석적·또박또박 존댓말 | 다크 |
| **한여름** | 로맨스 | 다정하고 살가운 말투 | 라이트 |
| **김도현** | 일상·에세이 | 편안하고 따뜻한 말투 | 라이트 |

🎙️ *"작가를 고르면 말투·장르·문체·화면 톤이 통째로 바뀝니다. 페르소나는 시스템 프롬프트 + 문체 예시(few-shot)로 구현했습니다."*

## 🖥️ S5. 타깃 & 문제 *(기획필수 ③)*
- **타깃**: 소설/창작을 하고 싶지만 *"백지에서 시작하기 막막한"* 사람
- **문제**: ① 빈 화면 공포 ② 길어지면 설정이 무너짐 ③ 내 문체가 안 남음 ④ 혼자라 안 이어짐
- → NodeVelture는 *대화*로 시작 장벽을 없애고, *기억·검수·문체*로 끝까지 같이 쓴다.

## 🖥️ S6. 핵심 사용 시나리오 3개 *(기획필수 ④)*
1. **시작이 막막할 때** — 작가 고르고 세계관 폼만 채우면 AI가 첫 장면을 던져줌 → 주인공으로 대답하며 전개
2. **설정을 더하고 싶을 때** — 메모로 *"사실 민준은 첫사랑"* 즉시 주입 → 이후 응답에 계속 반영
3. **한 챕터를 끝낼 때** — 「채팅 종료」 → 대화가 **작가 문체의 소설**로 변환 → 읽기·삽화·내보내기

## 🖥️ S7. 차별점 한 장 *(기획필수 ⑤ — 4부에서 수치로 증명)*

| 축 | 우리는 | ChatGPT는 |
|----|--------|-----------|
| ① **기억** | 오래된 설정을 의미검색해 다시 꺼냄 | 긴 맥락서 설정 흘림 |
| ② **검수** | 새 문장 ↔ 설정 모순 탐지 | 모순 그냥 통과 |
| ③ **문체** | 작가 문체 예시 few-shot 주입 | 일반적 문체 |
| + | 대화→소설 **변환** · 화자 고정 · 개인화(오답·취향) | 채팅 덩어리 · 휘발 |

🎙️ *"이 3축을 지금부터 숫자로 증명합니다."*

# PART 2 — 시스템 & 응답엔진 (5분)

## 🖥️ S8. 풀스택 아키텍처 *(기획필수 ⑥ · 가이드 §3.2)*
```
[클라이언트]  React + Vite (PC·모바일 반응형) — Vercel 배포
      │ REST + SSE(스트리밍)
[백엔드]     FastAPI — GCP Cloud Run (항상 켜진 HTTPS)
      ├─ Neon PostgreSQL (대화·소설·로그)
      ├─ Upstash Redis (히스토리·캐시·상태)
      └─ 응답엔진/임베딩 → Vertex AI
```
- 클라이언트 형태든 **"백엔드 → 응답엔진 호출 → 사용자 전달"** 흐름 동일 (가이드 §3.2 준수).

## 🖥️ S9. 응답 엔진 선택 — PERSO vs 대체 LLM *(기획필수 ⑦ · 가이드 §5.1·§6.2)*
- 가이드: **PERSO API 1순위, 제한 시 대체 LLM 동등 진행 가능**.
- 우리 선택: **Vertex AI Gemini 2.5 Flash-lite**(대체 LLM). 사유 = **한국어 품질·속도·GCP 크레딧·ADC(키리스)·IP차단 없음**.
- ★ **엔진을 환경변수로 스위칭** (`LLM_PROVIDER`·`USE_VERTEX`) — 가이드가 권장한 *"엔진 스위치 구조"* 그대로. 프로바이더 체인(**Gemini→Groq→OpenAI**)으로 **즉시 폴백** → 시연 중 한 엔진이 막혀도 끊김 없음.

🎙️ *"PERSO 할당이 떨어져도 환경변수 한 줄로 다른 모델로 시연을 이어갈 수 있게 설계했습니다."*

## 🖥️ S10. AI 파이프라인 — 구조화 응답
```
사용자 입력(주인공) ─▶ 프롬프트 조립
   (페르소나 + 세계관 + [기억 RAG] + 메모 + 화자고정규칙)
        ▼  LLM (json_mode)
   {narration, dialogue, speaker, state}  ← 나레이션/대사 분리
        ├─▶ 검수 RAG(모순 탐지)
        └─▶ 화면: 타자기 렌더 + 작가 리액션 + TTS
「채팅 종료」 ─▶ 대화로그 ─[문체 RAG few-shot]─▶ 작가 문체 단편소설
```

# PART 3 — AI 핵심: RAG 3종 (3분)

## 🖥️ S11. RAG 3종 — 검색증강으로 차별점 구현
| 구분 | 모듈 | 한 줄 |
|------|------|-------|
| ① **기억** | `memory.py` | 오래된 대화를 **의미검색**해 프롬프트에 주입 → 안 까먹음 |
| ② **검수** | `consistency.py` | 새 응답 ↔ 확립된 설정 **대조해 모순 탐지** |
| ③ **문체** | `style.py` | 작가 문체 예시를 장면별 검색해 소설 변환 **few-shot 주입** |

- 공통: **Gemini 임베딩 + 인앱 코사인 top-K** (별도 벡터DB 없이 단편 규모에 충분 — 대규모 시 pgvector).

🎙️ *"이 셋이 켜졌을 때 vs 꺼졌을 때 실제로 차이가 나는지 측정했습니다 — 다음 장입니다."*

# PART 4 — 정량 평가 ⭐ (6분) *(가이드 §8 평가지표 · §10 평가리포트)*

## 🖥️ S12. "말이 아니라 수치로" *(정량근거 핵심)*
- 측정: RAG 3종 **OFF vs ON**을 재현 스크립트로 비교 (`scripts/rag_demo·consistency_demo·style_demo`)
- 채점: **LLM-as-Judge 4축**(페르소나일관성·문체·정확성·완성도, 1~5점), 변동성은 **다회 평균**으로 보정

## 🖥️ S13. ① 기억 — "6턴 전 비밀을 기억하는가" ⭐ *(가장 강력)*
**실험**: 1턴에 비밀("민준=잠입 형사") 심기 → 잡담 5턴으로 밀어내기 → 6턴째 "민준의 정체?" 질문

| 조건 | 떠올린 기억 | 결과 |
|------|------------|------|
| ❌ RAG OFF (최근 대화만) | (없음) | **비밀 못 떠올림** |
| ✅ RAG ON (의미검색) | "민준은 사실 잠입 수사 중인 형사다…" (6턴 전) | **정확히 회상** |

🎙️ *"길어지면 까먹는 게 ChatGPT의 한계입니다. 우리는 6턴 전 비밀을 정확히 꺼내옵니다. **OFF=0, ON=정확** — 가장 압도적인 차이입니다."*

## 🖥️ S14. ② 검수 — "설정 모순을 잡는가"
**실험**: 확립된 설정("민준=잠입 형사")에 대해 모순/정상 문장 검수

| 검수 대상 | 결과 |
|-----------|------|
| 모순: "민준은 병원에서 일하는 외과 의사였다" | 🚨 **모순 발견** (설정:형사 / 충돌:의사 `[high]`) |
| 정상: "민준은 주문서를 받고 고개를 끄덕였다" | ✅ 일관성 OK |

🎙️ *"독자 입장에서 '어, 아까 형사라며?'를 AI가 대신 잡아줍니다."*

## 🖥️ S15. ③ 문체 — "작가 문체를 더 살리는가"
**실험**: 같은 장면을 한여름 작가로 소설화, few-shot OFF/ON **각 3회 생성·채점 평균**

| 조건 | 작가 문체 뚜렷함 | 합계(20점) |
|------|:---:|:---:|
| ❌ OFF (추상 규칙만) | 4.33 | 17.33 |
| ✅ ON (예시 few-shot) | **4.67** | **18.33** |
| **차이** | **+0.34** | **+1.00** |

🎙️ *(정직 버전)* *"양의 효과는 분명합니다. 격차가 작은 건 이미 작가 페르소나 규칙이 문체를 상당히 잡고 있어서고, 샘플을 늘리고 GPT로 바꾸면 더 벌어집니다."*

## 🖥️ S16. 종합 + 정직한 한계 *(신뢰성 어필)*
| RAG | 측정 | OFF | ON |
|-----|------|-----|-----|
| ① 기억 | 6턴 전 비밀 회상 | 실패 | **정확** |
| ② 검수 | 모순 탐지 | — | **정확 판별** |
| ③ 문체 | 문체 점수(3회 평균) | 17.33 | **18.33 (+1.00)** |

**+ 속도 개선**: 응답엔진 Vertex 전환으로 **8초 → ~2초**, Groq의 한자/일본어 언어누수 해소.

**정직한 한계**(먼저 말해 신뢰↑): 측정엔진 Groq 변동성 → 다회평균 / 언어누수 → GPT전환 시 해소·격차 확대 예상 / 문체 마진 작음 → 샘플풀 확대 계획(`evidence_report.py`).

🎙️ *"한계를 먼저 말씀드립니다. 그래도 ①기억·②검수는 이미 압도적이고, ③문체는 개선 경로가 명확합니다."*

# PART 5 — 멀티모달 & 개인화 (3분)

## 🖥️ S17. 멀티모달 *(가이드 §3.3 — 가산 영역)*
| 모달리티 | 우리 구현 | 기술 |
|----------|-----------|------|
| **음성 출력(TTS)** | 작가별 목소리로 첫 문장 낭독 | ElevenLabs |
| **이미지 생성(비전)** | 소설 장면을 삽화로 → DB 저장 | **Vertex Gemini 2.5 Flash Image** |
| **텍스트 QC** | 네이버 맞춤법기 + 개인 오답노트 | F-QC-02 |

🎙️ *"텍스트를 넘어 음성·이미지까지 — 삽화는 fal.ai에서 Vertex로 전환해 IP차단·비용 문제를 해결했습니다."*

## 🖥️ S18. 개인화 — "쓸수록 나를 안다" *(차별점)*
- **오답노트 능동 경고**: 자주 틀리는 맞춤법을 *쓰기 전에* 미리 짚음 (**반응형→예측형**)
- **취향 프로파일** · **화자 고정**(L1 검증+L2 프롬프트로 화자 안 흔들림)
- 경계: 개인화는 *코치/추천 층*만 — 소설 출력 문체엔 개인 정체성 주입 X

|------|-----------|

**흐름**: ① 작가 선택(테마 전환) → ② 세계관 폼 → ③ **대화형 창작**(주인공 대사 + @등장인물 + 메모 즉시주입 = 기억 RAG) → ④ **맞춤법 교정 + 오답 능동경고** → ⑤ **「채팅 종료」→ 작가 문체로 소설 자동 변환** → ⑥ 읽기 + **삽화 생성(Vertex)** → ⑦ 마이페이지(서재·취향·오답노트)

**시연 안전수칙**: 시작 전 **백엔드 워밍업**(cold-start 회피), 시드 데이터 준비, 라이브 변환 길어지면 백업 완성작으로 컷.

## 📎 부록 — 예상 Q&A
- **Q. 왜 PERSO 안 썼나요?** → 한국어 품질·속도·IP차단·키리스(ADC)·크레딧. 단 **엔진 스위치 구조**라 PERSO로 즉시 교체 가능.
- **Q. RAG 효과가 작은데?** → ①기억·②검수는 압도적, ③문체만 마진 작음(추상 규칙이 이미 강함). 샘플풀·GPT로 개선 경로 명확.
- **Q. 벡터DB 없이 괜찮나요?** → 단편 규모는 인앱 코사인으로 충분. 대규모 시 pgvector 전환 설계됨.
- **Q. 비용 관리는?** → `api_log` 호출 단위 토큰·비용 로그 + Redis 캐시 + 증분 요약 + 폴백.
