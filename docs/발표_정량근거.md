# NodeVelture 정량 근거 — "ChatGPT랑 뭐가 다른가"

> 발표용 자료. 측정 원본: [docs/rag/성능지표.md](rag/성능지표.md) · 재현 스크립트: [backend/scripts/](../backend/scripts/)
> 핵심 메시지: **차별점을 말이 아니라 수치로 증명한다.**

---

## 🎤 슬라이드 1 — 문제 제기

> "AI로 소설 쓰기? 그거 ChatGPT로도 되잖아요."

우리의 답은 **세 가지를 ChatGPT는 못/안 하고, 우리는 한다 — 그리고 그걸 수치로 보여준다**:

1. **기억(일관성)** — 대화가 길어져도 설정·캐릭터를 안 까먹는다 *(RAG)*
2. **검수** — 독자 입장에서 설정 모순을 잡아낸다
3. **문체** — 작가 4인의 문체를 실제로 더 살린다

---

## 🎤 슬라이드 2 — 차별점 3축 (한 장 요약)

| 축 | 한 줄 | ChatGPT는? |
|----|-------|-----------|
| ① 기억 | 오래된 설정을 **의미검색**해 다시 꺼내옴 | 긴 맥락에서 설정을 흘림 |
| ② 검수 | 새 문장 ↔ 확립된 설정을 대조해 **모순 탐지** | 모순을 그냥 통과 |
| ③ 문체 | 작가 문체 예시를 **few-shot 주입** | 일반적인 문체 |

> 셋 다 **RAG(검색증강)** + 자체 평가로 구현. 별도 벡터 DB 없이 in-app 코사인(단편 규모엔 충분).

## 🎤 슬라이드 3 — ① 기억: "6턴 전 비밀을 기억하는가" ⭐

**실험**: 1턴에 비밀("민준은 잠입 형사")을 심고 → 잡담 5턴으로 밀어낸 뒤 → 6턴째 "민준의 정체?" 질문. RAG OFF/ON 비교.

| 조건 | 떠올린 기억 | 결과 |
|------|------------|------|
| ❌ RAG OFF (최근 대화만) | (없음) | **비밀 못 떠올림** |
| ✅ RAG ON (의미검색) | "민준은 사실 잠입 수사 중인 형사다…" (6턴 전) | **정확히 회상** |

> 💬 멘트: *"길어지면 까먹는 게 ChatGPT의 한계입니다. 우리는 6턴 전에 심은 비밀을 정확히 다시 꺼내옵니다. 이게 우리 차별점의 직접 증거예요."*
> **OFF=0 / ON=정확** — 가장 압도적인 차이.

---

## 🎤 슬라이드 4 — ② 검수: "설정 모순을 잡는가"

**실험**: 확립된 설정("민준=잠입 형사")에 대해 모순/정상 문장을 검수.

| 검수 대상 | 결과 |
|-----------|------|
| 모순: "민준은 병원에서 일하는 외과 의사였다" | 🚨 **모순 발견** (설정: 형사 / 충돌: 의사 `[high]`) |
| 정상: "민준은 주문서를 받고 고개를 끄덕였다" | ✅ 일관성 OK |

> 💬 멘트: *"독자 입장에서 '어, 아까 형사라며?'를 AI가 대신 잡아줍니다."* — 강사님이 말한 "독자 입장 검수 어시스턴트"의 실동작.

---

## 🎤 슬라이드 5 — ③ 문체: "작가 문체를 더 살리는가"

**실험**: 같은 장면을 한여름 작가로 소설화, 문체 few-shot OFF/ON을 **각 3회 생성·채점 평균**(LLM 변동성 보정). 채점은 LLM-judge 4축(1~5점).

| 조건 | 작가 문체 뚜렷함 | 합계(20점) |
|------|:---:|:---:|
| ❌ OFF (추상 규칙만) | 4.33 | 17.33 |
| ✅ ON (예시 few-shot) | **4.67** | **18.33** |
| **차이** | **+0.34** | **+1.00** |

> 💬 멘트(정직 버전): *"양의 효과는 분명합니다. 다만 격차가 작은데, 이미 작가 페르소나 규칙이 문체를 상당히 잡고 있어서예요. 샘플을 늘리고 GPT로 바꾸면 격차가 더 벌어집니다."*

## 🎤 슬라이드 7 — 정직한 한계 & 다음 (신뢰성 어필)

발표에서 한계를 먼저 말하면 오히려 신뢰가 올라갑니다.

- **측정 엔진이 Groq**라 점수 변동이 있음 → **다회 평균**으로 봄
- **언어 누수**(Groq llama가 한자/일본어 섞음)로 점수·가독성 저하 → **GPT 전환 시 해소 + 격차 확대 예상**
- **문체 마진이 작은 이유**: 추상 규칙이 이미 강함 → 샘플 풀 확대로 개선
- **신뢰값 산출 계획**: 긴 시나리오 + 다회 평균 + GPT (`scripts/evidence_report.py`)

## 📊 공식 정량 평가표 (블랙박스 "검문소" 방식)

> 위 슬라이드 1~7이 **차별점(RAG ON/OFF)** 증거라면, 아래는 **공식 평가 방법론**(출력물 뒤에 독립 평가 모델을 붙여 점수화)에 맞춘 평가표다. 둘은 보완 관계.

### 검문소 파이프라인 — NodeVelture 적용 (텍스트 + 음성)
```
사용자 입력
   ▼
[NodeVelture = 블랙박스]  ← Vertex Gemini (대체 LLM, 내부 학습 안 함)
   │ 텍스트(대화/소설) ───► (검문소 A) GPT/Claude Judge → G-Eval(4축)
   │ TTS 음성(작가 낭독) ──► (검문소 B) Whisper STT       → CER
   ▼
사용자 화면  ◄──── (검문소 C) 서버 로그(api_log) → TTFB / 완료율
```
> 우리는 **영상·립싱크가 없으므로 LSE/FVD 생략**("만든 것만 평가"). 우리 세트 = **G-Eval + TTFB + 완료율 + CER**.

### 평가용 테스트셋 (창작 도메인 30~50개)
`testset.jsonl` — 카테고리 균형(일상 40 / 페르소나 30 / 엣지 20 / 안전 10):

| 카테고리 | 예시 입력 | 기대 |
|----------|-----------|------|
| 일상 | "...설마 안 오는 건가." | 작가가 상황을 이어받아 전개 |
| 페르소나 | (호러 백야로) "복도 끝에 뭔가 있어" | 백야 특유의 건조·서늘한 문체 유지 |
| 엣지 | @등장인물 화자 지정 / 6턴 전 설정 재질문 | 화자 고정 / 기억 회상 성공 |
| 안전 | 과도한 폭력·선정 요청 | 작가 톤 유지하며 수위 조절·우회 |

### 지표별 측정 방법 (요약)
- **G-Eval**: 채점관(GPT-4o, `temperature=0`)에 루브릭 + 페르소나 카드 + 대화를 주고 4축 1~5점. 같은 응답 **3회 평균**으로 편차↓. (이미 `evaluate.py`로 구현)
- **TTFB**: 백엔드에서 요청~첫 청크 시각차. `api_log`에 적재.
- **완료율**: 세션 시작/정상종료 이벤트 집계 = 정상종료/전체 ×100.
- **CER**: TTS 음성을 Whisper(`large-v3`)로 되받아쓰기 → 원문과 글자 단위 비교(한국어 주지표, WER은 보조).

### 최종 평가표 (현재값 + 목표 + 상태) — *시스템 지표 2026-06-15 라이브 실측*

| 레이어 | 지표 | 우리 결과 | 목표 | 상태 |
|--------|------|-----------|------|:----:|
| 대화 | G-Eval 문체 뚜렷함(1~5, 3회평균) | **4.67** (RAG ON) | ≥4.0 | ✅ |
| 대화 | G-Eval 완성도 합계(20점) | **18.33** (ON) | ≥17 | ✅ |
| 대화 | 차별점: 6턴 전 기억 회상 | OFF=실패 / **ON=정확** | ON 성공 | ✅ |
| 대화 | 차별점: 설정 모순 탐지 | **정확 판별**(형사 vs 의사 high) | 탐지 | ✅ |
| 시스템 | **완료율**(세션 정상종료) | **65.2%** (완료 30 / 전체 46) | ≥80% | ⚠️ |
| 시스템 | **TTFB**(전체 응답, *완성 후 1회 전송*) | **p50 8.7s / p95 16.5s** (신규세션 8회) | ≤1.5s | ❌ |
| 음성 | CER(작가 TTS 낭독) | 측정 예정(Whisper, 키 동작 필요) | ≤0.10 | ⏳ |
| 교차검증 | MOS(휴먼 5점, 5~10명) | 측정 예정 | 자동지표와 동일방향 | ⏳ |

> 측정 스크립트: `scripts/completion_rate.py`(완료율) · `scripts/ttfb_eval.py`(TTFB) · `scripts/cer_eval.py`(CER).

> 숫자 + **"그래서 무엇을 개선할지"** 까지 적어야 점수↑ (정직하게):
> - **TTFB p50 8.7s ❌** — 원인: 우리 스트림은 **토큰 스트리밍이 아니라 응답을 완성한 뒤 1회 전송**이라 TTFB ≈ *전체 응답시간*. 여기에 **Neon 리전 지연**(us-central1↔ap-southeast-1) + **RAG 임베딩 호출**이 더해짐. → 개선: ① **SSE 토큰 스트리밍**(첫 토큰을 즉시 흘려 체감 TTFB↓) ② **Neon 리전 정렬** ③ 워밍업/min-instances. *지표 정의를 '첫 토큰'으로 바꾸면 수치가 크게 내려감.*
> - **완료율 65.2% ⚠️** → 데모/테스트 세션의 미완주(active 16건)가 끌어내림. 정상 완주 흐름을 늘리면 80%+.
> - **문체 마진 작음** → 샘플풀 확대 + GPT 채점으로 격차 확대.
> - **CER·MOS** → CER은 Whisper+ElevenLabs 키 동작 환경에서 `cer_eval.py` 1회, MOS는 평가자 5~10명 폼.

### 발표용 한 줄
> *"차별점은 RAG ON/OFF로 증명했고, 품질은 공식 검문소(G-Eval·CER·TTFB·완료율)로 따로 채점합니다 — 만든 모달리티(텍스트·음성)만, 대신 확실하게."*

## 🔁 라이브 시연 / 재현 (질문 대비)

```bash
# backend 폴더, conda nodevelture, .env(DB·LLM 키) 필요
# ── 차별점(RAG ON/OFF) ──
python -m scripts.rag_demo          # ① 기억 (off/on) — 가장 임팩트
python -m scripts.consistency_demo  # ② 검수 (모순/정상)
python -m scripts.style_demo        # ③ 문체 (off/on 3회 평균)
python -m scripts.persona_eval      # 페르소나 분리 (블라인드 분류 정확도)
python -m scripts.evidence_report   # 맨손 vs 우리 종합
# ── 공식 평가표 시스템/음성 지표 ──
python -m scripts.completion_rate            # 완료율 (세션 상태 집계)   ← 65.2% 실측
python -m scripts.ttfb_eval <테스트세션id> 8 # TTFB p50/p95             ← p50 8.7s 실측
python -m scripts.cer_eval                    # CER (Whisper+ElevenLabs 필요)
```

> 발표 중 "진짜 되나요?" 질문 받으면 **① rag_demo를 라이브로** 돌리는 게 가장 강력합니다(OFF=못 떠올림 / ON=정확 회상이 즉석에서 보임).
