# 사용자 시나리오 (확정)

> 확정: 2026-06-08 · 이 문서가 사용 시나리오의 기준(source of truth).
> 기존 [planning/NodeVelture.md](planning/NodeVelture.md) §4의 모호했던 시나리오를 대체한다.
> 관련: [기능정의서](기능정의서.md), [문체모델 연동 설계](문체모델_연동_설계.md)

---

## 핵심 플로우

```
1) 작가 선택
2) 세계관 설정 (선택한 작가와 함께)
3) AI가 세계관 정보를 토대로 "상황(오프닝)" 부여
4) 사용자가 주인공이 되어 대사 입력
5) AI가 등장인물 대사 또는 작가 나레이션(지문)으로 응답
   → 둘 중 무엇으로 답할지는 입력 내용을 보고 AI가 알아서 구분
6) 사용자가 메모를 입력하면 → 그 내용을 추가 상황/설정으로 AI에게 주입
   (4~6을 반복하며 이야기 진행)

  ↓ 대화 종료

7) 누적된 대화를 토대로 소설 결과 도출 (선택한 작가의 문체로 변환)
```

---

## 단계별 정의

### 1) 작가 선택
- 메인 화면에서 작가 4명 중 선택: 백야(호러·미스터리) / 차로운(추리) / 한여름(로맨스) / 김도현(일상·에세이)
- 선택한 작가가 **그 세션의 문체·장르 정체성**을 결정한다.

### 2) 세계관 설정
- 선택한 작가와 함께 장르/배경/등장인물(조연)을 잡는다.
- 결과: 세계관 + 조연 캐릭터들이 DB에 저장됨.

### 3) AI의 상황 부여 (오프닝)
- 채팅 진입 시 AI가 세계관 정보를 토대로 첫 상황을 제시한다.
- 예) "비 오는 날, 너는 오래된 카페 구석에서 누군가를 기다리고 있다."

### 4) 사용자 = 주인공, 대사 입력
- 사용자는 1인칭 주인공으로서 대사·행동을 입력한다.
- 예) "기억하세요? 저 여기 자주 왔는데."

### 5) AI 응답 — 등장인물 또는 작가 나레이션 (AI가 자동 구분)
- **등장인물 응답**: 장면에 조연이 있고 사용자가 말을 걸면, 그 조연이 대사·행동으로 반응.
- **작가 나레이션 응답**: 상황 묘사가 필요하면 작가가 지문(나레이션)으로 장면을 이어간다.
- **핵심**: 사용자가 모드를 고르지 않는다. AI가 입력을 보고 알아서 둘 중 하나(또는 혼합)로 응답.
- 응답은 **대사 + 지문**을 함께 사용해 몰입감을 준다.

### 6) 메모 = 추가 상황/설정 주입 ("작가" 기능)
- 오른쪽 메모 칸에 추가하고 싶은 설정을 적으면, AI에게 **추가 상황으로 주입**된다.
- 예) "사실 민준은 주인공의 첫사랑이다", "이 카페는 곧 문을 닫는다"
- **메모는 적으면 즉시(바로 다음 응답부터) 반영된다.** (저장 버튼 대기 없음)
- 한 번 주입된 설정은 이후 응답에도 계속 유지된다 (→ 세계관 일관성 / 장기 기억).
- 즉 사용자는 *주인공으로 연기(채팅)* 하면서 동시에 *작가로 세계를 손본다(메모)*.

### 7) 소설 변환
- 대화가 끝나면 누적 대화 로그를 **선택한 작가의 문체로** 소설 초안으로 변환한다.
- (문체 모델 후처리는 [문체모델 연동 설계](문체모델_연동_설계.md) 참고)

## 걸어보는 예시 (한여름 / 로맨스)

```
[3] AI 상황 부여
   비 오는 오후, 너는 창가 자리에서 식어가는 커피를 앞에 두고 있다.

[4] 사용자(주인공) 입력
   "...설마 안 오는 건가."

[5] AI 응답 (작가 나레이션 — 조연이 없으니 지문으로 이어감)
   빗줄기가 유리창에 길을 냈다. 문에 달린 종이 울릴 때마다 고개를 들었지만,
   매번 낯선 얼굴이었다.

[6] 사용자 메모 입력
   "민준이 우산 없이 뛰어 들어온다"

[4] 사용자 입력
   "민준아, 여기!"

[5] AI 응답 (등장인물 — 메모로 등장한 민준이 대사로 반응)
   민준: "헉... 미안, 늦었지." 어깨가 흠뻑 젖은 채 그가 맞은편에 앉았다.
```

## 구현 매핑 (참고)

| 시나리오 | 구현 위치 |
|----------|-----------|
| 1) 작가 선택 | `GET /authors`, main 페이지 |
| 2) 세계관 설정 | `/worlds`, `/worlds/{id}/characters`, worldview 페이지 |
| 3) 상황 부여 | 채팅 진입 시 AI 오프닝 (구현 필요) |
| 4~5) 대화·응답 | `POST /chats/{id}/messages` → `GET /chats/{id}/stream` |
| 5) 등장인물/나레이션 자동 구분 | 프롬프트가 "입력에 따라 대사 또는 지문으로 응답"하도록 설계 ([personas.py](../backend/app/core/personas.py)) |
| 6) 메모 주입 | 메모 내용 → 세션 컨텍스트(상황/설정)에 누적 주입 ([chats.py](../backend/app/api/v1/endpoints/chats.py) `build_prompt`) |
| 7) 소설 변환 | `POST /sessions/{id}/novel/generate` + 작가 문체 |

---

## 이 시나리오로 정리된 핵심 결정

- **채팅 모드 토글 없음** — AI가 등장인물/나레이션을 자동 구분 (5단계).
- **작가의 역할** = ① 세계관 설계 길잡이(1·2단계) + ② 소설 변환 문체(7단계). 채팅 본문 전면엔 안 나섬.
- **메모 = 작가 기능** — 별도 "작가모드" 채팅이 아니라, 설정을 주입하는 기능으로 재정의.
- **AI 응답은 대사 + 지문 혼합** — 몰입감 우선.
