# 자기 평가서 — 윤정 (팀장 · 백엔드)

> ⚠️ 초안입니다. 표현·강조점을 본인 톤으로 다듬어 확정하세요.

## 담당 역할
팀장 / 백엔드 코어 · 멀티모달 통합 · 배포 · 정량 평가

## 한 일 (핵심)

- **백엔드 코어** — FastAPI 채팅/세션/소설 파이프라인, 작가 페르소나 시스템, **RAG 3종**(장기 기억·설정 검수·문체 few-shot), 맞춤법 교정(F-QC-02)·개인 오답노트.
- **멀티모달** — 삽화 엔진 **fal.ai → Vertex Gemini Image 전환**(결제·차단 이슈 우회) + DB 영속, **작가 음성 리액션**(ElevenLabs)을 **Vercel 서버리스 프록시**로 구현해 Cloud Run 키 제약 우회.
- **문맥 기반 리액션** — 사용자 입력 + 작가 답변 문맥으로 감정을 잡아 작가 말투로 생성(풀 폴백 유지).
- **성능/UX** — 마이페이지 대시보드 쿼리 병렬화(6.9s→~2s), 세계관→채팅 전환 병렬화, alert→토스트 등.
- **배포·운영** — Cloud Run·Vercel 배포 트러블슈팅, 환경변수/시크릿 함정 체크리스트화, 서비스 전체 점검(e2e + 코드 감사).
- **정량 평가** — 완료율·TTFB·CER·호출비용 측정 스크립트 + 실측, 발표 정량근거 문서.

## 잘한 점
- **문제 정의 → 진단 → 해결**의 흐름. 막연한 "안 된다"를 로그·실측으로 원인 규명(배포 차단 우회, 머지 충돌 해결, 502 진단 등).
- 차별점을 **수치**로 증명하고 문서로 남겨 재현 가능하게 함.
- 팀장으로서 배포 함정·워크플로를 공유해 팀 전체 시행착오를 줄임.

## 아쉬운 점
- 응답 **토큰 스트리밍 미구현**으로 체감 지연(TTFB)을 끝까지 못 줄임.
- "혼자 장면" 모순 등 일부를 **키워드 휴리스틱**으로 처리 — 더 견고한 방식 여지.
- 자동 테스트 부족 — 출시 점검을 수동 e2e로 메움.

## 배운 점
- 클라우드 배포의 현실적 제약(데이터센터 IP 차단·키 정책)과 **벤더 우회 설계**(서버리스 프록시).
- 멀티 LLM **폴백 체인**과 RAG의 품질↔비용 트레이드오프를 데이터로 보는 법.
